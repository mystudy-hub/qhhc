评审日期：2026-10-22

范围：单一期货品种加权指数上的实时行情识别；不讨论换月与交易执行

## 1. 结论

**V3 已适合进入最小实现和逐根回放验证。建议先做一次有限的 V3.1 修订，解决执行时序和状态出口，不再继续扩张事件类型。**

V2 的主要问题得到实质处理：指数输入契约、来源拒绝回退、指数精度、滚动突破计数、LPS 依附期限、回调长度、确认优先于创高重置、内部支撑失效、UT 测试、高潮簇快照、活动率与累计努力，以及无 Spring 的 Phase C 范围声明。这些不应再次作为未修复问题提出。

目前剩余问题主要发生在不同章节的交界处：某条公式单独看正确，但在规定顺序下尚不可用；某个状态能够进入，却没有完整退出；一个事实可以作为历史记录保留，但其当前有效性和证据计票没有完全统一。

以下 P1 表示正式冻结完整实现前应修复；P2 表示需要统一口径或补充验收。它们不是对损失概率或交易风险的评分。

## 2. 主要发现

### R1｜P1：当前根外侧计数在确认之后才更新

位置：V3 第 5.5 节，394—395 行；第 7.5 节，736—737 行；第 9.4 节，1053—1055 行。

维持确认使用 `outside_up_streak_t`，处理顺序却是：确认 → 超时 → 更新 outside_streak。如果严格按这一顺序实现，确认阶段只能读取 t−1 的已保存值；临时提前计算的实现则会得到不同结果。

反例：期限末根开始时 streak=2，当根收盘仍在阻力外，应当变为3并确认。按字面顺序，确认阶段看到2，随后假设过期，最后才更新到3，可能被迫走 `late_acceptance`。本应及时确认的事件被改变了状态与时间。

建议把“计算当前可观测值”和“写入下一根使用的基准状态”分开：

```text
读取 t-1 状态 + 已收盘的 t 根
计算当根 RVOL/NS/NetMove、outside_streak_t 等临时值
执行失效、事实、确认、超时与状态转换
更新 ATR/Bv 等供下一根使用的状态，写出 t 快照
```

此处提前算当根计数不构成未来信息。需要继续保持事件比较用 ATR/Bv 排除当前根。

### R2｜P1：late_acceptance 有进入状态，没有独立失败出口

位置：V3 第 7.5 节，751—757 行；第 9.1 节，977—985 行。

过期后的外侧维持可以把区间改为 `exit_up_accepted`，但事件 `hypothesis_id=null`。后续失败规则依赖候选或已确认的有效性假设；无活动假设时回区间的行只覆盖 `exit_up_candidate`，未覆盖这种已接纳状态。

反例：S=90、R=100、ε=0.2，原假设过期后完成晚接纳；随后两根收盘为99.5、99.4，满足原突破的回区间失败条件。但原假设已经过期，区间也已不是 `exit_up_candidate`，表中没有唯一转换。

主市场状态可能因价格在区间内而显示 range，但区间仍残留 accepted，失败事件、Phase E 当前支持及之后再次越界的转换没有完整依据。

建议为“已接纳的区间突破”建立独立有效性记录，例如 `acceptance_id`，或明确区间级失败规则不依赖 hypothesis 是否存在。晚接纳不复活旧假设，但必须具备自己的失败与终止出口。

### R3｜P1：依附级联的执行时点与文字保证不一致

位置：V3 第 7.1 节，608—617 行；第 7.6 节，807、824—827 行；第 9.4 节，1050—1054 行。

文字保证“来源已终止时，依附规则已使本候选终止”，实际顺序却到确认和超时之后才执行级联。父对象在失效检查阶段结束后，子对象的确认检查可能仍被执行，再在当根末尾失效。

部分路径可能同时命中自身价格失效而掩盖问题，但不能依赖这种偶然重合。还应明确：父对象曾 confirmed、后来因当前有效期届满而 expired，如何影响依附的 Phase D；现有通用过期规则重点写的是“未确认而 expired”。

建议区分三种操作：

1. 价格失效与其他已确定终止：立即向依附对象传播，再执行依附确认。
2. 窗口超时：保留末根确认机会，确认全部处理完后再过期并级联。
3. 已确认对象的当前有效性过期：按依附类型终止或原子地转移引用，不能由实现遍历顺序决定。

LPS 确认可以反向确认来源突破，因此不必强制所有确认单向拓扑排序；应将该组转换定义为一次事务。新 LPS 承接旧 LPS 和 Phase D 引用，也应按同样原则处理。

### R4｜P2：内部 LPS 会被通用分型段落覆盖

位置：V3 第 7.6 节，765—773 行。

来源表规定内部 JOC/SOS 产生 `LPS_INTERNAL`，但新增的“确认时子类型”段落无条件写成 `LPS_AT_CREEK` 或 `LPS_ABOVE_CREEK`，并按外部 R 比较。

例：外部 R=110，内部 Creek=105，回调低点105.1。按来源表应为 INTERNAL；按后文条件因105.1≤110+ε，会被标成 BUEC，尽管它没有回测外部突破边界。

建议分支写清：只有“外部突破来源”按 R 分成 AT/ABOVE；内部两类来源始终为 INTERNAL，并保存具体内部参照位。向下镜像也采用同样明确分支。

### R5｜P2：新 ST 观察可能覆盖旧 ST 的有效反应

位置：V3 第 7.2 节，666—672 行；第 9.4 节，1051—1053 行。

流程先检测新事实，最新 ST 立即替换待反应的 q，再检查反应。某根既可以是新的 ST 观察，又可以是旧 ST 的有效后续反应；替换后它变成 r=q，必须满足额外的阳线条件，可能漏掉原本合格的确认。

构造：S=100、ε=0.1、A_SC=1、Effort_SC=3、NS_SC_ref=4。旧测试最高价101；下一根 O=101.5、H=101.6、L=100.3、C=101.3、RVOL=0.5、NS=1.3。

- 下一根满足新 ST 的位置、量能和波幅条件。
- 对旧测试，它收于101以上，满足 r>q 的反应条件。
- 替换为新 q 后，它是阴线，不满足 r=q 的严格条件。

建议先对仍有效的旧测试检查当根反应，未确认时才更新 q；或保留一个有界的测试观察集合并按确定的优先级确认。Spring Test/UT Test 也应明确多次观察的选择规则，不能只靠引用 ST 公式解决。

### R6｜P2：波浪不可评估时，最终方向仍可能被输出为 neutral

位置：V3 第 8.3 节，906、927—931 行；第 10.5 节，1147 行。

波浪不足或模块关闭时，A/P/D 为 `not_evaluable`；没有路径成立时却统一输出 neutral。这混淆了“数据足够，但方向条件不成立”和“关键证据根本不可评估”。

建议为路径使用三值结果：成立、不成立、不可评估。没有成立路径时：若必需条件缺失，整体方向为 `not_evaluable/unknown`；只有足够条件可评估且均不成立，才输出 neutral。保留各组值及缺项，供界面区分。

### R7｜P2：迟到信号评价仍可能包含可用前的部分 K 线

位置：V3 第 4.8 节，319 行；第 11.4 节，1244—1246 行。

把锚点改成可用时刻之前最后一根收盘，修复了 V2 的明显旧锚点问题。但“锚点之后的下一根”可能已经在信号可用前开始。

例：5分钟信号根结束于10:05:00，10:05:02才可用。下一根是10:05—10:10，其中上障碍在10:05:01已被触及。使用完整 OHLC 会把这次触及算进可用后的预测结果。现有 `pre_crossed` 检查只到锚点之前，覆盖不了这两秒。

仅有 OHLC 时应明确定义：预测从 `bar_start>=available_at` 的首根完整 K 线开始，配套登记参考价与 ATR；或将包含可用时刻的 K 线标为时序歧义，不推断其中高低点发生顺序。有逐笔数据时才从精确时间截取路径。

锚点使用的数据还必须同时满足实际已到达，而不只是 bar_end 不晚于 available_at。

### R8｜P2：confirm_step 的“最小距离”与严格不等式差一档

位置：V3 第 3.1 节，139 行；第 7.2 节，671—672 行；第 7.6 节，800 行。

价格分辨率0.01、confirm_step=0.01，前高100.00，收盘100.01已超过前高一个分辨率单位，但 `C>H+confirm_step` 不通过，最低要100.02。

若定义确实是“至少超过一个单位”，应采用 `C>=H+confirm_step`，向下用相应的 `<=`。如果有意要求严格超过一个额外缓冲，则保留公式但修正术语和用例。不要在不改版本的情况下静默改变不等式。

## 3. 需要澄清、但不必继续扩展功能的事项

### 3.1 快照中的 trend_context 时间下标

V3 第 5.1 节将 `trend_context_t` 定义为截至 t−1，第 6.0/6.2 节却从 p−1 快照读取名为 trend_context 的字段。如果保存的是 `trend_context_(p-1)`，其数据实际只到 p−2。

建议快照明示 `trend_now_asof_bar` 和 `context_for_next_bar`，事件 p 使用截至 p−1 的趋势；不要让同名字段既表示“这一根的前置背景”，又表示“下一根可用的前置背景”。这属于潜在一根延迟，不应误称未来泄漏。

### 3.2 B 组应明确计历史确认还是当前有效确认

912—915 行统计最近已确认序列，但没有写明是否排除后来 invalidated 的结构。历史发生事实可以保留，却不能未经说明继续当作当前正向支持。

建议并存两类字段：历史已确认序列列表、截至 t 当前有效的支持证据。当前 B 组采用后者；失败序列可以作为独立的反向/失败特征研究。若选择仍计入历史事实，则应明确其目的和与失效证据的联合处理。

### 3.3 OI 保留描述角色，并补齐缺失和零分母处理

第 4.6 节 OIz 的历史变化中位数可能为0；OI也可能缺失或晚到。应返回不可评估而不是无穷大，记录独立可用时间。

第 1.2 节关于 OI 增减的措辞宜改为“在同一固定统计口径下反映未平仓合约总量的净变化”。聚合 OI 变化不能逐笔证明所有成交双方同时开仓或同时平仓，且成分变化可能影响统计。V3 默认不据此判定方向的选择应保留。

### 3.4 不必把所有未覆盖结构继续塞进 V3

V3 已诚实标明无 Spring/UT 的 Phase C、跨周期和曲线参照位不在范围内。内部 LPS 及低量有效推进已增加入口。经典方法允许多个 LPS，也允许供应枯竭后在较小需求下推进，相关概念可参见 [Wyckoff Analytics 教程](https://www.wyckoffanalytics.com/wyckoff-method/)。

下一步应以结构覆盖率、延迟和失效分布决定是否扩展，而不是为了接近示意图无限增加条件。现有严格子类型和主规则分开的设计可以保留。

## 4. 建议的有限修订方案

### 4.1 先冻结一份无歧义的每根处理顺序

```text
1. 校验数据；读取此前状态。
2. 用当根已收盘数据计算临时特征与当前 streak。
3. 已有对象的失效与当前有效性终止，立即向依附对象传播。
4. 对已有测试/回调检查当根响应；按明确优先级处理新事实与新观察。
5. 新候选的 INCL 检查；执行允许的确认及联动状态转换。
6. 窗口末根机会已处理完后，再执行超时和相应级联。
7. 更新供下一根使用的基准、摆动点和波浪；按实际可用时间生成新增证据。
8. 更新方向、当前状态和阶段；区间新版本按约定于下一根启用。
9. 完整写出状态变化与快照。
```

该顺序仍需按具体事件给出依赖关系，尤其是 LPS 对来源突破的反馈确认，以及新 LPS 替代旧 LPS。不能仅调换一个通用步骤就假定所有竞态消失。

### 4.2 补充少量高价值构造验收

| 编号 | 构造 | 期望 |
|---|---|---|
| R01 | 期限末根使 streak 从2到3 | 原假设及时 confirmed，不走 late_acceptance |
| R02 | 晚接纳后连续两根回区间 | 接纳失效、区间状态和当前阶段有完整出口 |
| R03 | 父对象当根终止，子对象其他条件同时满足 | 不先输出子对象确认再撤销 |
| R04 | 内部 Creek 回调确认 | 仍为 LPS_INTERNAL，不归类外部 BUEC |
| R05 | 新 ST 当根也是旧 ST 的反应，且该根收阴 | 旧测试可正常确认 |
| R06 | 波浪模块关闭或完成波不足 | 方向不可评估，不能伪装为中性 |
| R07 | 信号可用前1秒触及下一根中的障碍 | 不能算可用后的预测成功 |
| R08 | 价格只超过前高一个 resolution | 按预先声明的最小距离语义判断 |
| R09 | 趋势恰在 p−1 改变，p 检测高潮簇 | 使用准确的 p−1 上下文，而非 p−2 |
| R10 | 已确认支撑测试随后失效 | 历史事实保留，当前 B 组按声明规则降级 |

### 4.3 再做最小实现与样本回放

保留8个首轮校准参数和当前模块范围。先实现单指数、单周期的逐根处理，验证前缀一致性、状态转换和上述边界用例，再开展跨年份、波动环境的滚动样本外研究。

第一批结果应包含：覆盖率、不可评估比例、确认延迟、失败/超时分布、独立区间数，以及相对趋势与普通突破基准的增量。理论语义成立和规则可以运行，都不能替代这些结果。
